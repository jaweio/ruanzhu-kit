# AIGC 检测与去除（Step 6 细则）

> 目的：让说明书、申请表文案回到真实操作手册该有的样子——以操作动线为主、事实具体、结构不模板化。
> 不是为了掩盖什么：所有内容仍须与源码一致，**禁止为降分编造事实**。
> 文风规范本身见 [writing-style.md](writing-style.md)，本文件只讲检测工具和闭环流程。

---

## 1. 工具一览

| 脚本 | 做什么 | 会不会改文件 |
| --- | --- | --- |
| `scripts/aigc_check.py` | 逐块打分、按章节汇总、列高风险段落和原因 | 不改 |
| `scripts/aigc_rewrite.py` | 机械清理 + 生成《AIGC改写任务单.md》 | 仅 `--apply` 时改，自动留 `.bak` |
| `scripts/aigc_rules.py` | 两者共用的规则库（黑名单、营销词、事实锚点正则等） | — |
| `scripts/aigc_calibrate.py` | 用朱雀真实结果校准：回归自测 / 导入新报告 | 只写 `assets/aigc-calibration/` |

全部是 Python 标准库，离线运行，不上传任何内容。

单文件可直接传 `.md` `.txt` `.docx` `.pdf`（PDF 需 pypdf 或 pdftotext，会做 NFKC 归一化）。扫描范围（传目录时）：各份软著目录下的 `*.md`（跳过 `源程序提取/`、`说明书章节/`、`源码材料清单.md`、报告本身），`auto-fill/config.json` 里 ≥30 字的字段（主要是 `mainFunction`），以及没有同名 `.md` 的 `.docx`。

## 2. 打分口径（2026-09 按朱雀样本校准）

每块 0–100，越高越像模板化 AI 文；文件分 = 按字数加权平均（代码块权重 0.3，标题和目录不计）。另按块分档统计**人工 / 疑似 / AI 字数占比**，口径同朱雀报告（占比不是“作者用 AI 的概率”）。

| 块类型 | 底分 | 加分项 | 减分项 |
| --- | --- | --- | --- |
| 散文段 | 25 | 黑名单 +18/处（封顶 3）；营销词 +8/个；括号补注每千字 ≥10 个 +20（≥15 个 +30）；粗体引导词 ≥2 +20；FAQ 模板 ≥2 +25；句中分号过多 +10；抽象名词过密 +15；无事实锚点 +12；模板化开头 +10；≥4 句且句长均匀 +12；超 5 句 +8；占位符 +30 | 操作/条件句 −6/句（封顶 −18）；经验性表达 −8（FAQ 段不享受减分） |
| 列表 | 20 | 非操作列表：同一开头 +25、冒号定义式 ≥3 +15、条目等长 +20、几乎无事实 +15，外加上面的结构项 | 操作步骤列表（≥50% 条目是“单击/输入/选择…”或含“控件名”）直接 10 分 |
| 表格 | 40 | 黑名单 +10/处、占位符 +30 | —（实测 0.24–0.997，按“疑似”处理） |
| 代码块 | 5 | — | — |

| 分档 | 含义 | 处理 |
| --- | --- | --- |
| < 35 | 低，接近人工档 | 可以进入 PDF 渲染 |
| 35–55 | 中 | 按任务单改掉 ≥35 分的块 |
| ≥ 55 | 高，模板化明显 | 该章节按“（一）功能说明 /（二）操作步骤 /（三）异常处理”重写 |

**当前校准结果**（`python3 scripts/aigc_calibrate.py`）：24 段样本，二分类准确率 88%，Spearman +0.38。人工样本只有 3 段，两段表格为主的人工样本被判“疑似”，属已知偏差。

**局限**：这是规则启发式，不做语言模型困惑度计算。它能较好区分“概述腔 / 排比腔”和“操作手册腔”，但分不出 0.8 和 0.99 的差别，对纯表格段基本靠猜。最终以外部检测为准。

### 校准数据得出的三条结论

1. 操作步骤体（祈使句 + 控件名 + 取值约束 + 失败分支）是唯一稳定判人工的写法。
2. 事实密度与朱雀结果几乎不相关——事实多但用“**X**：…（补注）；”排比写，照样 0.99。
3. 表格不稳定，FAQ 模板稳定判 AI。

### 维护校准库

```bash
S=<skill目录>/scripts
python3 $S/aigc_calibrate.py                          # 改 aigc_rules / aigc_check 后必跑，准确率不应下降
python3 $S/aigc_calibrate.py --import-report 朱雀报告.pdf --note "项目X-第3批"
python3 $S/aigc_calibrate.py --add 原文.txt --ratio 0.1555 --note "项目X-操作章节(人工)"
```

朱雀只对判 AI 的批次提供可导出的分段报告；判人工的批次通常只有页面上的一个 ratio，用 `--add` 手工录入。人工样本越多，校准越可靠。导入前先脱敏（产品名、人名、地址）。

## 3. 闭环流程

```bash
M=soft-copyright-materials/01-XXX软件
S=<skill目录>/scripts

# ① 检测，出报告
python3 $S/aigc_check.py $M --report $M/AIGC检测报告.md

# ② 机械清理：先预览 diff，确认没把句子删残再 --apply（任务单会按问题附改法和示范）
python3 $S/aigc_rewrite.py $M
python3 $S/aigc_rewrite.py $M --apply

# ③ 语义改写：Claude 按 $M/AIGC改写任务单.md 逐条改写 .md 源文件
#    每条都要回源码查事实；查不到的删掉空话，而不是编

# ④ 复测，作为渲染前闸门（有占位符或任一文件 >35 分 → 退出码 1）
python3 $S/aigc_check.py $M --report $M/AIGC检测报告.md --fail-above 35

# ⑤ 通过后才进入 render_pdfs.py；docx/pdf 一律由改好的 .md 重新生成
# ⑥ 终检：对渲染出的 PDF 再测一次（送检和提交的都是 PDF 文本）
python3 $S/aigc_check.py $M/软件说明书.pdf --max-ai-ratio 10
```

一般 2 轮就能压到 35 以下。第 3 轮还下不去，多半是那一章只有概括、没有操作——回到界面或源码，把它改成“进入哪里 → 单击什么 → 失败怎么办”；实在没有可操作的内容，就缩短这一章。

### 机械清理会做什么

只做删了不伤事实与语法的替换：营销形容词（强大的/完善的/先进的…）、“值得注意的是”→“注意，”、“综上所述”删除、“包括但不限于”→“包括”、“进行配置”→“配置”、“旨在”→“用于”、“显著/有效”删除、“一站式的”删除、列表条目末尾“；”→“。”、列表“- **X**：”去加粗。代码块和行内代码不动。

它**不会**处理“提供…能力”“覆盖…体系”、括号补注、FAQ 模板这类问题——这些必须结合源码重写，统一进任务单，任务单里每条会附对应的改法和示范。

注意：删完修饰语，句子偶尔会变得干巴（如“具备完善的功能”→“具备功能”）。这种句子仍会被检测为高风险并进任务单，第 ③ 步一起重写即可。

### Claude 执行第 ③ 步的要求

1. 一次处理一个文件，按任务单编号顺序改，改完在任务单对应条目下填入改后文本，便于用户核对。
1. 高分段落优先改结构：能力罗列 → “（一）功能说明 /（二）操作步骤 /（三）异常处理”；括号补注并入句子；FAQ 改“现象 | 原因 | 处理”表格。
2. 每条改写前先 Grep/Read 相关源码，改后文本里的每个路径、类名、数字都必须能在项目里找到。
3. 多份软著时，改写不能引入其他软著的功能或源码文件（黄金原则 2）。
4. `mainFunction` 改写后重新数字数，保持 500–1300 字。
5. 改完跑第 ④ 步，把前后分数对比告诉用户。

## 4. 外部检测（可选，需用户同意）

本地分数达标后，如用户还想用商业 AIGC 检测服务复核：

- 把说明书或申请表文案上传到第三方网站属于**对外发送材料**，必须先征得用户明确同意；更稳妥的是让用户自己上传。
- 上传前确认材料里没有 API Key、Token、手机号、内网地址（注意事项里的脱敏要求同样适用）。
- 外部结果回来后，把判为 AI 的段落贴回来，按本文件第 3 节 ③ 的要求改写，再本地复测。
