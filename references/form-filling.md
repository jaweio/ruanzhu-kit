# 申请表填报（Step 8 细则）

> 方式：**Claude 通过浏览器插件操作用户已登录的 Chrome**（Claude in Chrome；没有插件时用 computer-use 控制桌面 Chrome）。
> 不用 Playwright、不开无头浏览器、不装 npm 依赖。
> 终点：**保存至草稿箱**。「确认填报」由用户本人点击。

---

## 1. 三条硬规矩

1. **账号是用户的**：登录由用户本人完成，agent 不输入账号、密码、验证码，也不代办实名认证。页面要求登录就把浏览器交回用户，等对方说“登好了”再继续。
2. **值只来自 `auto-fill/config.json`**：字段内容一律复制配置里的值，页面上不即兴编写、不临场润色。配置里还有【待填写】就先回到 Step 4/6 补，不要带着占位符去填表。
3. **停在草稿**：填到「保存至草稿箱」为止。**不得点击**「确认填报」「提交申请」一类按钮——正式提交是不可逆的对外动作，必须用户本人操作。

## 2. 操作前准备

```bash
# ① 字段汇总与校验（拿不到的字段会报出来）
python3 scripts/application_form.py --config soft-copyright-materials/ruanzhu.config.json --strict

# ② 生成操作计划：逐控件列出「填什么值 / 怎么核对」，长文本单独落盘
python3 scripts/form_plan.py --config <材料目录>/auto-fill/config.json --out <材料目录>/填表操作计划.md
```

计划里每个字段标了类型（text / textarea / select / choice / date / number / file）、长度上限、是否需要回读。
主要功能这类长文本会写到 `auto-fill/长文本/mainFunction.txt`，**整段粘贴，不要逐字输入**（手打容易丢字、超时、触发页面校验）。

## 3. 浏览器操作要点

| 环节 | 做法 |
| --- | --- |
| 打开页面 | 导航到 `https://register.ccopyright.com.cn/r11.html#/application`；若跳登录页，交回用户 |
| 认结构 | 先 `read_page` 拿到控件树和 ref，按 label 文本定位，不靠坐标乱点；截图只在需要看版式时用 |
| 填文本 | 优先用表单输入工具按 ref 填值；页面是 Vue 表单，填完要让控件失焦（Tab 或点空白），否则值不进模型 |
| 下拉/单选 | 展开后按选项文字点选，填完回读一次确认选中的是目标项 |
| 日期 | 填完按 Esc 关掉日期面板，再回读文本框 |
| 长文本 | 从 `长文本/*.txt` 复制整段填入，**填完必须回读字数**，确认没被截断 |
| 上传 | 用文件上传工具选 `auto-fill/config.json` 里那两个 PDF 的绝对路径；等待上传完成提示，再回读文件名 |
| 翻页 | 每步填完先回读关键字段，确认无误再点「下一步」；页面报红就停下看提示，不要反复重试 |

## 4. 回读核对（必须做）

确认信息页逐项回读，按这个格式记下页面上的实际值：

```json
{"softwareName": "…", "version": "…", "completionDate": "…", "published": "未发表",
 "sourceLines": "…", "mainFunction": "…（整段）", "programPdf": "…", "docPdf": "…"}
```

```bash
python3 scripts/form_plan.py --config <材料目录>/auto-fill/config.json --verify 回读.json
```

脚本逐字段比对：普通字段比文本，长文本比字数（防截断），PDF 比文件名。**有不一致就回去改，不要先保存草稿**。
`published` 等标了“填完回读”的字段必须出现在回读 JSON 里，漏了会被判为未核对。

## 5. 保存与交接

1. 核对全部一致 → 点击「保存至草稿箱」→ 等保存成功提示。
2. 把结果告诉用户：填了哪些字段、上传了哪两个 PDF、草稿保存时间。
3. 明确提示：**请你本人在浏览器里核对确认页，无误后点「确认填报」提交**。浏览器保持打开，不要关。

## 6. 多份软著

一份一份来，每份填完保存草稿、回读核对通过，再开始下一份。
特别核对软件全称、版本号、开发完成日期、源程序量不要串份——这四项串了最难发现。

## 7. 异常处理

| 情况 | 处理 |
| --- | --- |
| 页面改版，控件对不上 | 先 `read_page` 看实际结构，按新 label 填；改动较大时停下告诉用户，并更新 `assets/r11-field-map.json` |
| 字段报“超出长度” | 不要自行删字，回到 `ruanzhu.config.json` 改，重跑 `application_form.py` |
| 上传失败 | 确认 PDF 路径存在、大小符合官网限制；重试两次不行就停下问用户 |
| 出现验证码 | 交回用户本人处理，agent 不识别验证码 |
| 会话过期 | 交回用户重新登录，登录后从当前步骤继续 |

## 8. 备选：Playwright 脚本

`scripts/auto-fill/auto-fill.js` 是早期的脚本化方案，需要 `npm install playwright`，用本机 Chrome Profile 跑有头浏览器。
页面结构稳定、要批量重复填报时可以用；日常优先用浏览器插件方式，省依赖、页面变了也能随机应变。
该脚本同样会在启动前校验配置（有占位符/字数不达标直接中止），并且只保存草稿、不提交。
