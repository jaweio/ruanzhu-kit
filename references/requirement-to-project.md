# Step 0：需求 → 真实 uni-app 项目

用户只有一句需求（如“做一个游戏盒子 App”）、还没有代码时使用。目标是**先做出能运行的真实软件**，再走 Step 1–9 生成材料。

## 红线

- 不为不存在的软件生成说明书、源码 PDF 或截图；材料只能描述已实现并能运行的功能。
- 不凑行数：禁止复制文件、堆注释、生成无用代码；`spec_gate.py` 会拦截重复代码和空壳页面。
- 不用设计稿、Mockup 冒充运行截图；截图必须来自运行中的 App（H5 用 `capture.py --target web`，小程序用 `--target miniprogram`）。
- 不打包他人的游戏、图片、音乐等素材；只用自有或已授权内容，或只做列表与跳转。
- 开发完成日期填真实完成日；代码由 AI 辅助编写，著作权归属由用户确认。

## 流程

1. **产品规格**：从需求拆出 4–8 个模块，写 `<项目>/产品规格.json`，逐模块列页面路径和要点，**与用户确认后再写代码**：

   ```json
   {
     "name": "星游游戏盒子",
     "stack": "uni-app",
     "modules": [
       {"name": "游戏列表", "pages": ["pages/game/list"], "features": ["分类筛选", "下拉刷新", "分页加载"]},
       {"name": "游戏详情", "pages": ["pages/game/detail"], "features": ["简介", "截图轮播", "收藏"]}
     ]
   }
   ```

2. **生成项目**：在用户指定的**空目录**用 Vue 3 + uni-app（CLI 版 `vite` 模板或 HBuilderX 模板）实现规格里的全部页面，以及真实的状态管理、接口封装和本地模拟数据层。每完成一个模块提交一次 git，保留真实开发记录。
3. **构建运行**：`npm install && npm run build:h5`（HBuilderX 项目用“发行 › 网站-H5”），再用 `npm run dev:h5` 启动，逐页点通。
4. **闸门**：

   ```bash
   python3 <skill目录>/scripts/spec_gate.py --project <项目目录> --spec <项目目录>/产品规格.json --require-build
   ```

   检查每个规格页面已登记在 `pages.json`（含分包）且不是空壳（默认 ≥30 行有效代码）、自有有效代码 ≥3000 行（≈60 页）、重复代码 ≤30%、H5 构建产物存在。不通过就补真实功能，或者减少模块、如实少交页数（`--min-lines` 调低，源程序材料按实际页数提交）。

5. **进入 Step 1**：`manual_spec.py --repo <项目目录>` 抽取素材；截图、演示数据、说明书、源码、检测、填表都按原流程执行。说明书只写规格里已通过闸门的模块。
